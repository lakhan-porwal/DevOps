ORSProject04 CI/CD DEPLOYMENT GUIDE
GitHub -> Jenkins (Windows) -> Docker Desktop -> Docker Hub -> AWS EC2
Language: English
IMPORTANT: The Jenkins pipeline will handle the EC2 SSH connection, Docker installation, Docker network setup, MySQL startup/setup, and application deployment. Manual SSH commands in PowerShell are only for troubleshooting.

============================================================
1. PROJECT FLOW
============================================================

1. The source code is stored on GitHub.
2. Jenkins checks out the source code from GitHub.
3. Maven builds the ORSProject04.war file.
4. Docker Desktop builds the application image on the Jenkins machine.
5. Jenkins tags the image and pushes it to Docker Hub.
6. Jenkins connects to AWS EC2 over SSH.
7. EC2 pulls the latest application image from Docker Hub.
8. EC2 runs the ORS application container and connects it to the existing MySQL container.
9. Open the application in a browser and test the login.

IMPORTANT DETAILS:
- Jenkins URL: http://localhost:8085
- GitHub repository: https://github.com/lakhan-porwal/ORSProject04-Complete.git
- Branch: main
- Project folder: ORSProject04
- Docker Hub image: lakhanporwal/orsproject04:latest
- Jenkins Docker Hub credential ID: docker-creds-new
- Jenkins AWS SSH credential ID: aws-ec2-ssh
- EC2 public IP Stop/Start ke baad change ho sakta hai. AWS Console se current IP check karo.

============================================================
2. AWS CREATE AN AWS EC2 INSTANCE
============================================================

1. Open the AWS Console and go to EC2.
2. Click Launch instance.
3. Set the instance name to: ORSProject04-Server-New
4. Select Ubuntu Server 24.04 LTS (64-bit x86).
5. Choose a suitable instance type available in your account, such as t3.micro.
6. Create or select this key pair: ORS-deploy-key
7. . Download the .pem file and store it securely. Do not upload this file to GitHub.
8. Launch the instance.
9. After launch, configure the security group.
10. Continue only when the instance is Running and its status checks have passed.

IMPORTANT:
- Do not terminate the instance while troubleshooting.
- Stop and Terminate are different actions.
- Terminating an instance can permanently delete it.

============================================================
3. SECURITY GROUP RULES
============================================================

In the AWS Console:
EC2 -> Instances -> your instance -> Security -> Security Group
-> Inbound rules -> Edit inbound rules

Rules:
A. SSH
- Port: 22
- Source: My IP (recommended)

B. HTTP
- Port: 80
- Source: 0.0.0.0/0
- Only if the application is served on port 80.

C. HTTPS
- Port: 443
- Source: 0.0.0.0/0
- Only if HTTPS is configured.

D. Custom TCP
- Port: 8080
- Source: 0.0.0.0/0
- Required to access the Tomcat application from a browser.

E. MySQL port 3308 (optional)
- Only if direct MySQL access from a trusted IP is required.
- Do not expose MySQL to the public internet. The application connects to MySQL through the Docker network.

============================================================
4. CONNECT TO EC2 OVER SSH THROUGH JENKINS
============================================================

Running a manual SSH command from Windows PowerShell is not a required deployment step.
Jenkins connects to EC2 over SSH using Jenkins credential ID: aws-ec2-ssh.

Jenkins -> Manage Jenkins -> Credentials mein ye credential pehle se create karo:
- Kind: SSH Username with private key
- Username: ubuntu
- Private key: contents of the ORS-deploy-key.pem private key
- ID: aws-ec2-ssh

The Jenkinsfile runs this SSH test in the "Connect to AWS and Prepare EC2" stage:
echo AWS_SSH_OK

AWS_HOST Replace the placeholder in the Jenkinsfile with the EC2 instance’s CURRENT public IPv4 address.
The EC2 instance must be Running, and SSH port 22 must be reachable from the Jenkins host.
StrictHostKeyChecking=no skips the host-key prompt for first-time automation; in production, verifying and pinning the host key is safer.

============================================================
5. INSTALL DOCKER ON EC2 THROUGH JENKINS
============================================================

Instead of running commands manually in an SSH terminal, the Jenkins pipeline’s "Connect to AWS and Prepare EC2" stage runs these commands on EC2:

sudo apt-get update
sudo apt-get install -y docker.io
sudo systemctl enable --now docker
sudo docker --version

If the pipeline stage fails, inspect the error for that stage in Jenkins Console Output.
Ubuntu package repositories and internet access must be available on EC2.

============================================================
6. CREATE THE DOCKER NETWORK THROUGH JENKINS
============================================================

Application JDBC URL:
jdbc:mysql://mysql:3306/p04

The application container must be able to resolve the MySQL hostname "mysql" on the Docker network.

The Jenkinsfile’s "Ensure Docker Network and MySQL" stage checks for the network and creates it only if it does not exist:
sudo docker network inspect ors-network || sudo docker network create ors-network

If the network already exists, do not delete it. Do not delete existing networks or volumes, as this could put database data at risk.

============================================================
7. SET UP MYSQL THROUGH JENKINS AND PRESERVE DATA
============================================================

Existing setup:
- Database: p04
- Container: mysql-container
- Docker network: ors-network
- Persistent volume: mysql-data

In the Jenkinsfile’s "Ensure Docker Network and MySQL" stage:
1. The network ors-network is created if it does not exist.
2. The mysql-data volume is created if it does not exist.
3. If mysql-container already exists, it is not recreated.
4. If the container is stopped, it is started.
5. The pipeline attempts to connect the existing container to the network.

IMPORTANT:
- The pipeline uses the official mysql:8.0 image for a first-time setup. If your existing container was created from the custom image lakhanporwal/mysql:8.0, preserve that existing container; the pipeline does not replace it.
- Do not manually delete the existing MySQL container or volume. Protecting existing database data is essential.
- If a root password is already set in the existing container, the MYSQL_ROOT_PASSWORD environment variable will not change it.
- For a fresh database, the example root password is "root". Use a strong password in production and store credentials in Jenkins Credentials.
- After MySQL setup, verify that the p04 database and required tables are present.
- If the network alias "mysql" is already attached, the network-connect command may report a duplicate-alias error. In that case, check Console Output and inspect the network. Do not change existing network settings blindly.

MySQL check commands (zaroorat par Jenkins ke SSH command stage mein add/run kiye ja sakte hain):
sudo docker exec mysql-container mysql -uroot -proot -e "SHOW DATABASES;"
sudo docker exec mysql-container mysql -uroot -proot -D p04 -e "SELECT 1 AS connection_test;"

============================================================
8. APPLICATION DATABASE CONFIGURATION
============================================================

The system.properties file inside the deployed WAR must contain these values:

url=jdbc:mysql://mysql:3306/p04
driver=com.mysql.cj.jdbc.Driver
username=root
password=root

Other connection-pool settings:
DATABASE=JDBC
service=javaBean
acquireIncrement=1
initialPoolSize=1
maxPoolSize=5
minPoolSize=1
timeout=10

File path:
WEB-INF/classes/com/sunilos/p4/bundle/system.properties

The hostname must be "mysql", not "localhost", because the application and MySQL run in separate containers.

============================================================
12. COMPLETE JENKINSFILE
============================================================

This Jenkinsfile performs GitHub checkout, Maven build, Docker image build/push,
AWS SSH connection, Docker installation on EC2, Docker network/MySQL
setup, application deployment, and container verification through Jenkins.

BEFORE RUNNING:
- Replace AWS_HOST with the current EC2 public IPv4 address.
- docker-creds-new aur aws-ec2-ssh Jenkins credentials must be configured.
- Docker Desktop must be running on Windows.
- Do not delete the existing MySQL container or volume.
- SSH port 22 must be reachable from the Jenkins host through the EC2 security group.
- Verify the existing MySQL data and password settings.

NOTE: This is a starter pipeline. If the existing MySQL container’s network
alias is already attached, the network-connect command may fail.
Check Console Output. Before running this with important production data,
validate the pipeline in a test environment.

pipeline {
    agent any

    environment {
        DOCKER_IMAGE = 'orsproject04'
        DOCKERHUB_IMAGE = 'lakhanporwal/orsproject04:latest'
        AWS_HOST = 'YOUR_EC2_PUBLIC_IP'
    }

    stages {
        stage('Git Checkout') {
            steps {
                git branch: 'main',
                    url: 'https://github.com/lakhan-porwal/ORSProject04-Complete.git'
            }
        }

        stage('Build WAR') {
            steps {
                dir('ORSProject04') {
                    bat '''
                        set "JAVA_HOME=C:\\Program Files\\Java\\jdk-21.0.12"
                        set "PATH=%JAVA_HOME%\\bin;C:\\apache-maven-3.10.0-bin-maven-3.10.0\\bin;%PATH%"
                        call mvn clean package
                        if errorlevel 1 exit /b 1
                        if not exist target\\ORSProject04.war exit /b 1
                    '''
                }
            }
        }

        stage('Build Docker Image') {
            steps {
                dir('ORSProject04') {
                    bat 'docker build -t %DOCKER_IMAGE%:latest .'
                }
            }
        }

        stage('Tag Docker Image') {
            steps {
                bat 'docker tag %DOCKER_IMAGE%:latest %DOCKERHUB_IMAGE%'
            }
        }

        stage('Docker Hub Login and Push') {
            steps {
                withCredentials([usernamePassword(
                    credentialsId: 'docker-creds-new',
                    usernameVariable: 'DOCKER_USER',
                    passwordVariable: 'DOCKER_PASS'
                )]) {
                    bat '''
                        @echo off
                        echo %DOCKER_PASS% | docker login -u %DOCKER_USER% --password-stdin
                        if errorlevel 1 exit /b 1
                        docker push %DOCKERHUB_IMAGE%
                        if errorlevel 1 exit /b 1
                        docker logout
                    '''
                }
            }
        }

        stage('Connect to AWS and Prepare EC2') {
            steps {
                withCredentials([sshUserPrivateKey(
                    credentialsId: 'aws-ec2-ssh',
                    keyFileVariable: 'SSH_KEY',
                    usernameVariable: 'SSH_USER'
                )]) {
                    bat '''
                        @echo off
                        ssh -i "%SSH_KEY%" -o StrictHostKeyChecking=no %SSH_USER%@%AWS_HOST% "echo AWS_SSH_OK"
                        if errorlevel 1 exit /b 1

                        ssh -i "%SSH_KEY%" -o StrictHostKeyChecking=no %SSH_USER%@%AWS_HOST% "sudo apt-get update && sudo apt-get install -y docker.io && sudo systemctl enable --now docker && sudo docker --version"
                        if errorlevel 1 exit /b 1
                    '''
                }
            }
        }

        stage('Ensure Docker Network and MySQL') {
            steps {
                withCredentials([sshUserPrivateKey(
                    credentialsId: 'aws-ec2-ssh',
                    keyFileVariable: 'SSH_KEY',
                    usernameVariable: 'SSH_USER'
                )]) {
                    bat '''
                        @echo off
                        ssh -i "%SSH_KEY%" -o StrictHostKeyChecking=no %SSH_USER%@%AWS_HOST% "sudo docker network inspect ors-network >/dev/null 2>&1 || sudo docker network create ors-network"
                        if errorlevel 1 exit /b 1

                        ssh -i "%SSH_KEY%" -o StrictHostKeyChecking=no %SSH_USER%@%AWS_HOST% "sudo docker volume inspect mysql-data >/dev/null 2>&1 || sudo docker volume create mysql-data"
                        if errorlevel 1 exit /b 1

                        ssh -i "%SSH_KEY%" -o StrictHostKeyChecking=no %SSH_USER%@%AWS_HOST% "sudo docker container inspect mysql-container >/dev/null 2>&1 || sudo docker run -d --restart unless-stopped --name mysql-container --network ors-network --network-alias mysql -p 3308:3306 -e MYSQL_ROOT_PASSWORD=root -e MYSQL_DATABASE=p04 -v mysql-data:/var/lib/mysql mysql:8.0"
                        if errorlevel 1 exit /b 1

                        ssh -i "%SSH_KEY%" -o StrictHostKeyChecking=no %SSH_USER%@%AWS_HOST% "sudo docker start mysql-container"
                        if errorlevel 1 exit /b 1

                        ssh -i "%SSH_KEY%" -o StrictHostKeyChecking=no %SSH_USER%@%AWS_HOST% "sudo docker network connect --alias mysql ors-network mysql-container 2>/dev/null || true"
                    '''
                }
            }
        }

        stage('Deploy Application to AWS') {
            steps {
                withCredentials([sshUserPrivateKey(
                    credentialsId: 'aws-ec2-ssh',
                    keyFileVariable: 'SSH_KEY',
                    usernameVariable: 'SSH_USER'
                )]) {
                    bat '''
                        @echo off
                        ssh -i "%SSH_KEY%" -o StrictHostKeyChecking=no %SSH_USER%@%AWS_HOST% "sudo docker pull %DOCKERHUB_IMAGE%"
                        if errorlevel 1 exit /b 1

                        ssh -i "%SSH_KEY%" -o StrictHostKeyChecking=no %SSH_USER%@%AWS_HOST% "sudo docker rm -f ors-container 2>/dev/null || true"

                        ssh -i "%SSH_KEY%" -o StrictHostKeyChecking=no %SSH_USER%@%AWS_HOST% "sudo docker run -d --restart unless-stopped --name ors-container --network ors-network -p 8080:8080 %DOCKERHUB_IMAGE%"
                        if errorlevel 1 exit /b 1
                    '''
                }
            }
        }

        stage('Verify Deployment') {
            steps {
                withCredentials([sshUserPrivateKey(
                    credentialsId: 'aws-ec2-ssh',
                    keyFileVariable: 'SSH_KEY',
                    usernameVariable: 'SSH_USER'
                )]) {
                    bat '''
                        @echo off
                        ssh -i "%SSH_KEY%" -o StrictHostKeyChecking=no %SSH_USER%@%AWS_HOST% "sudo docker ps && sudo docker logs --tail 50 ors-container"
                        if errorlevel 1 exit /b 1
                    '''
                }
            }
        }
    }

    post {
        success {
            echo 'Pipeline stages completed. Browser test is still required.'
        }
        failure {
            echo 'Pipeline failed. Open Console Output and inspect the first failed stage.'
        }
    }
}

============================================================

sudo docker exec ors-container getent hosts mysql
