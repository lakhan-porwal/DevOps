ORSProject04 CI/CD DEPLOYMENT GUIDE
GitHub -> Jenkins (Windows) -> Docker Desktop -> Docker Hub -> AWS EC2
Language: Hinglish
IMPORTANT: EC2 SSH connection, Docker installation, Docker network setup, MySQL startup/setup aur application deployment Jenkins pipeline ke through chalenge; PowerShell mein manual SSH steps sirf troubleshooting ke liye hain.

============================================================
1. PROJECT FLOW
============================================================

1. Source code GitHub par store hota hai.
2. Jenkins GitHub se source code checkout karta hai.
3. Maven ORSProject04.war file build karta hai.
4. Docker Desktop Jenkins machine par application image banata hai.
5. Jenkins image ko tag karke Docker Hub par push karta hai.
6. Jenkins SSH ke through AWS EC2 se connect karta hai.
7. EC2 Docker Hub se latest application image pull karta hai.
8. EC2 ORS application container run karta hai aur existing MySQL container se connect karta hai.
9. Browser mein application open karke login test kiya jata hai.

IMPORTANT DETAILS:
- Jenkins URL: http://localhost:8085
- GitHub repository: https://github.com/lakhan-porwal/ORSProject04-Complete.git
- Branch: main
- Project folder: ORSProject04
- Docker Hub image: lakhanporwal/orsproject04:latest
- Jenkins Docker Hub credential ID: docker-creds-new
- Jenkins AWS SSH credential ID: aws-ec2-ssh
- EC2 public IP Stop/Start ke baad change ho sakta hai. AWS Console se current IP check karo.

============================================================
2. AWS EC2 INSTANCE CREATE KARNA
============================================================

1. AWS Console open karo aur EC2 par jao.
2. Launch instance par click karo.
3. Instance ka naam rakho: ORSProject04-Server-New
4. Ubuntu Server 24.04 LTS (64-bit x86) select karo.

6. Key pair create ya select karo: ORS-deploy-key
7. .pem file download karke safe jagah rakho. Is file ko GitHub par upload mat karna.
8. Instance launch karo.
9. Launch hone ke baad security group configure karo.
10. Instance Running ho aur status checks pass hon, tab aage badho.

IMPORTANT:
- Troubleshooting ke liye instance ko terminate mat karna.
- Stop aur Terminate alag actions hain.
- Terminate karne se instance permanently delete ho sakta hai.

============================================================
3. SECURITY GROUP RULES
============================================================

AWS Console mein:
EC2 -> Instances -> apna instance -> Security -> Security Group
-> Inbound rules -> Edit inbound rules

Rules:
A. SSH
- Port: 22
- Source: My IP (recommended)

B. HTTP
- Port: 80
- Source: 0.0.0.0/0
- Sirf tab jab application port 80 par serve ho.

C. HTTPS
- Port: 443
- Source: 0.0.0.0/0
- Sirf tab jab HTTPS configure ho.

D. Custom TCP
- Port: 8080
- Source: 0.0.0.0/0
- Tomcat application ko browser se access karne ke liye.

E. MySQL port 3308 (optional)
- Sirf trusted IP se direct MySQL access ki zaroorat ho tab.
- MySQL ko public internet par expose mat karo. App Docker network ke through MySQL se connect hoti hai.

============================================================
4. EC2 SSH CONNECT JENKINS KE THROUGH
============================================================

Windows PowerShell se manual SSH command run karna is deployment ka required step nahi hai.
Jenkins EC2 se SSH ke through connect karega, using Jenkins credential ID: aws-ec2-ssh.

Jenkins -> Manage Jenkins -> Credentials mein ye credential pehle se create karo:
- Kind: SSH Username with private key
- Username: ubuntu
- Private key: ORS-deploy-key.pem ki private key contents
- ID: aws-ec2-ssh

Jenkinsfile ke "Connect to AWS and Prepare EC2" stage mein ye SSH test hota hai:
echo AWS_SSH_OK

AWS_HOST ko Jenkinsfile mein EC2 ke CURRENT public IPv4 address se replace karo.
EC2 Running hona chahiye, aur security group mein SSH port 22 tumhare Jenkins host ke outbound access ke liye reachable hona chahiye.
StrictHostKeyChecking=no first-time automation ke liye host prompt ko skip karta hai; production mein host key ko verify/pin karna safer hai.

============================================================
5. EC2 PAR DOCKER INSTALL JENKINS KE THROUGH
============================================================

Manual SSH terminal mein commands chalane ke bajay Jenkins pipeline ka "Connect to AWS and Prepare EC2" stage ye commands EC2 par chalata hai:

sudo systemctl enable --now docker
sudo docker --version

Pipeline stage fail ho to Jenkins Console Output mein isi stage ka error dekho.
EC2 par Ubuntu package repositories aur internet access available hona chahiye.

============================================================
6. DOCKER NETWORK JENKINS KE THROUGH CREATE KARNA
============================================================

Application JDBC URL:
jdbc:mysql://mysql:3306/p04

Application container ko Docker network par MySQL ka hostname "mysql" resolve karna chahiye.

Jenkinsfile ke "Ensure Docker Network and MySQL" stage mein network ko idempotently create/check kiya jata hai:
sudo docker network inspect ors-network || sudo docker network create ors-network

Agar network pehle se hai, use delete nahi karna. Database records preserve karne ke liye existing network/volume ko delete mat karna.

============================================================
7. MYSQL JENKINS KE THROUGH SETUP KARNA AUR DATA PRESERVE KARNA
============================================================

Existing setup:
- Database: p04
- Container: mysql-container
- Docker network: ors-network
- Persistent volume: mysql-data

Jenkinsfile ke "Ensure Docker Network and MySQL" stage mein:
1. ors-network exist na kare to create hota hai.
2. mysql-data volume exist na kare to create hota hai.
3. mysql-container pehle se exist karta hai to usko recreate nahi kiya jata.
4. Container stopped ho to start kiya jata hai.
5. Existing container ko network se connect karne ki koshish hoti hai.

IMPORTANT:
- Pipeline first-time setup ke liye mysql:8.0 official image use karta hai. Agar tumhara existing container custom image lakhanporwal/mysql:8.0 se bana tha, existing container ko preserve karo; pipeline use replace nahi karti.
- Existing MySQL container/volume ko manually delete mat karna. Existing database data ko protect karna zaroori hai.
- Database root password existing container mein pehle se set hai to MYSQL_ROOT_PASSWORD environment variable us password ko change nahi karta.
- Fresh database ke liye default example root password "root" hai. Production mein strong password use karo aur credentials ko Jenkins Credentials mein rakho.
- MySQL setup complete hone ke baad verify karo ki p04 database aur required tables present hain.
- Agar network alias "mysql" pehle se attached hai, network connect command duplicate-alias error de sakti hai; aise case mein Console Output check karke network inspect karo. Existing network settings ko blindly change mat karo.

MySQL check commands (zaroorat par Jenkins ke SSH command stage mein add/run kiye ja sakte hain):
sudo docker exec mysql-container mysql -uroot -proot -e "SHOW DATABASES;"
sudo docker exec mysql-container mysql -uroot -proot -D p04 -e "SELECT 1 AS connection_test;"

12. COMPLETE JENKINSFILE
============================================================

Ye Jenkinsfile GitHub checkout, Maven build, Docker image build/push,
AWS SSH connection, EC2 par Docker installation, Docker network/MySQL
setup, application deployment aur container verification Jenkins se karta hai.

BEFORE RUNNING:
- AWS_HOST ko current EC2 public IPv4 address se replace karo.
- docker-creds-new aur aws-ec2-ssh Jenkins credentials configure hon.
- Docker Desktop Windows par running ho.
- Existing MySQL container/volume ko delete mat karna.
- EC2 security group mein SSH port 22 tumhare Jenkins host se reachable ho.
- MySQL ke liye existing data/password settings verify karna.

NOTE: Ye starter pipeline hai. Agar existing MySQL container ka network
alias pehle se attached hai, network-connect command fail ho sakti hai.
Console Output verify karo. Important production data ke saath run karne
se pehle test environment mein validate karo.

pipeline {
    agent any

    environment {
        DOCKER_IMAGE = 'orsproject04'
        DOCKERHUB_IMAGE = 'lakhanporwal/orsproject04:latest'
        AWS_HOST = 'YOUR_EC2_PUBLIC_IP'
    }

    stages {
        stage('Git Checkout') {
            steps {
                git branch: 'main',
                    url: 'https://github.com/lakhan-porwal/ORSProject04-Complete.git'
            }
        }

        stage('Build WAR') {
            steps {
                dir('ORSProject04') {
                    bat '''
                        set "JAVA_HOME=C:\\Program Files\\Java\\jdk-21.0.12"
                        set "PATH=%JAVA_HOME%\\bin;C:\\apache-maven-3.10.0-bin-maven-3.10.0\\bin;%PATH%"
                        call mvn clean package
                        if errorlevel 1 exit /b 1
                        if not exist target\\ORSProject04.war exit /b 1
                    '''
                }
            }
        }

        stage('Build Docker Image') {
            steps {
                dir('ORSProject04') {
                    bat 'docker build -t %DOCKER_IMAGE%:latest .'
                }
            }
        }

        stage('Tag Docker Image') {
            steps {
                bat 'docker tag %DOCKER_IMAGE%:latest %DOCKERHUB_IMAGE%'
            }
        }

        stage('Docker Hub Login and Push') {
            steps {
                withCredentials([usernamePassword(
                    credentialsId: 'docker-creds-new',
                    usernameVariable: 'DOCKER_USER',
                    passwordVariable: 'DOCKER_PASS'
                )]) {
                    bat '''
                        @echo off
                        echo %DOCKER_PASS% | docker login -u %DOCKER_USER% --password-stdin
                        if errorlevel 1 exit /b 1
                        docker push %DOCKERHUB_IMAGE%
                        if errorlevel 1 exit /b 1
                        docker logout
                    '''
                }
            }
        }

        stage('Connect to AWS and Prepare EC2') {
            steps {
                withCredentials([sshUserPrivateKey(
                    credentialsId: 'aws-ec2-ssh',
                    keyFileVariable: 'SSH_KEY',
                    usernameVariable: 'SSH_USER'
                )]) {
                    bat '''
                        @echo off
                        ssh -i "%SSH_KEY%" -o StrictHostKeyChecking=no %SSH_USER%@%AWS_HOST% "echo AWS_SSH_OK"
                        if errorlevel 1 exit /b 1

                        ssh -i "%SSH_KEY%" -o StrictHostKeyChecking=no %SSH_USER%@%AWS_HOST% "sudo apt-get update && sudo apt-get install -y docker.io && sudo systemctl enable --now docker && sudo docker --version"
                        if errorlevel 1 exit /b 1
                    '''
                }
            }
        }

        stage('Ensure Docker Network and MySQL') {
            steps {
                withCredentials([sshUserPrivateKey(
                    credentialsId: 'aws-ec2-ssh',
                    keyFileVariable: 'SSH_KEY',
                    usernameVariable: 'SSH_USER'
                )]) {
                    bat '''
                        @echo off
                        ssh -i "%SSH_KEY%" -o StrictHostKeyChecking=no %SSH_USER%@%AWS_HOST% "sudo docker network inspect ors-network >/dev/null 2>&1 || sudo docker network create ors-network"
                        if errorlevel 1 exit /b 1

                        ssh -i "%SSH_KEY%" -o StrictHostKeyChecking=no %SSH_USER%@%AWS_HOST% "sudo docker volume inspect mysql-data >/dev/null 2>&1 || sudo docker volume create mysql-data"
                        if errorlevel 1 exit /b 1

                        ssh -i "%SSH_KEY%" -o StrictHostKeyChecking=no %SSH_USER%@%AWS_HOST% "sudo docker container inspect mysql-container >/dev/null 2>&1 || sudo docker run -d --restart unless-stopped --name mysql-container --network ors-network --network-alias mysql -p 3308:3306 -e MYSQL_ROOT_PASSWORD=root -e MYSQL_DATABASE=p04 -v mysql-data:/var/lib/mysql mysql:8.0"
                        if errorlevel 1 exit /b 1

                        ssh -i "%SSH_KEY%" -o StrictHostKeyChecking=no %SSH_USER%@%AWS_HOST% "sudo docker start mysql-container"
                        if errorlevel 1 exit /b 1

                        ssh -i "%SSH_KEY%" -o StrictHostKeyChecking=no %SSH_USER%@%AWS_HOST% "sudo docker network connect --alias mysql ors-network mysql-container 2>/dev/null || true"
                    '''
                }
            }
        }

        stage('Deploy Application to AWS') {
            steps {
                withCredentials([sshUserPrivateKey(
                    credentialsId: 'aws-ec2-ssh',
                    keyFileVariable: 'SSH_KEY',
                    usernameVariable: 'SSH_USER'
                )]) {
                    bat '''
                        @echo off
                        ssh -i "%SSH_KEY%" -o StrictHostKeyChecking=no %SSH_USER%@%AWS_HOST% "sudo docker pull %DOCKERHUB_IMAGE%"
                        if errorlevel 1 exit /b 1

                        ssh -i "%SSH_KEY%" -o StrictHostKeyChecking=no %SSH_USER%@%AWS_HOST% "sudo docker rm -f ors-container 2>/dev/null || true"

                        ssh -i "%SSH_KEY%" -o StrictHostKeyChecking=no %SSH_USER%@%AWS_HOST% "sudo docker run -d --restart unless-stopped --name ors-container --network ors-network -p 8080:8080 %DOCKERHUB_IMAGE%"
                        if errorlevel 1 exit /b 1
                    '''
                }
            }
        }

        stage('Verify Deployment') {
            steps {
                withCredentials([sshUserPrivateKey(
                    credentialsId: 'aws-ec2-ssh',
                    keyFileVariable: 'SSH_KEY',
                    usernameVariable: 'SSH_USER'
                )]) {
                    bat '''
                        @echo off
                        ssh -i "%SSH_KEY%" -o StrictHostKeyChecking=no %SSH_USER%@%AWS_HOST% "sudo docker ps && sudo docker logs --tail 50 ors-container"
                        if errorlevel 1 exit /b 1
                    '''
                }
            }
        }
    }

    post {
        success {
            echo 'Pipeline stages completed. Browser test is still required.'
        }
        failure {
            echo 'Pipeline failed. Open Console Output and inspect the first failed stage.'
        }
    }
}
