ORSProject04 CI/CD DEPLOYMENT GUIDE GitHub -> Jenkins (Windows) ->
Docker Desktop -> Docker Hub -> AWS EC2

============================================================ 1. PROJECT
FLOW ============================================================

1.  Source code is stored in GitHub.
2.  Jenkins checks out the source code.
3.  Maven builds the ORSProject04 WAR file.
4.  Docker Desktop builds the application image on the Jenkins machine.
5.  Jenkins tags the image and pushes it to Docker Hub.
6.  Jenkins connects to the AWS EC2 instance through SSH.
7.  EC2 pulls the latest application image from Docker Hub.
8.  EC2 runs the ORS application container and connects it to the
    existing MySQL container.
9.  The application is opened in a browser and login is tested.

Important: - Jenkins is running on Windows at http://localhost:8085. -
The project repository used in this guide is:
https://github.com/lakhan-porwal/ORSProject04-Complete.git - Branch:
main - Project folder inside the repository: ORSProject04 - Docker Hub
image: lakhanporwal/orsproject04:latest - Jenkins Docker Hub credential
ID: docker-creds-new - Jenkins AWS SSH credential ID: aws-ec2-ssh -
Current EC2 public IP at the time these notes were written:
54.87.174.177 - Public IP can change after Stop/Start unless an Elastic
IP is attached. Always check the current IP in EC2 details.

============================================================ 2. CREATE
THE AWS EC2 INSTANCE
============================================================

1.  Open AWS Console and go to EC2.
2.  Select Launch instance.
3.  Give the instance a name, for example: ORSProject04-Server-New
4.  Select Ubuntu Server 24.04 LTS (64-bit x86).
5.  Select an instance type that is available and suitable for your
    account. The instance used in this setup was t3.micro.
6.  Create or select a key pair: ORS-deploy-key
7.  Download and keep the .pem key file safely. In this setup, the local
    path was: C:porwal-deploy-key.pem
8.  During the Launch instance wizard, do not add or change the
    security-group inbound rules. Launch the instance first using the
    normal wizard settings.
9.  After the instance has launched, open the instance details and
    configure the security group as described in Section 3.
10. Wait until the instance is Running and its status checks show 3/3
    checks passed.

Do not terminate the instance to troubleshoot it. Stop/Start is
different from Terminate.

============================================================ 3. ADD
SECURITY-GROUP RULES AFTER THE INSTANCE IS LAUNCHED
============================================================

1.  EC2 -> Instances -> select ORSProject04-Server-New.
2.  Open the Security tab.
3.  Click the attached security group.
4.  Open Inbound rules -> Edit inbound rules.
5.  Add the rules below, then save.

Rule A: - Type: SSH - Protocol: TCP - Port: 22 - Source: My IP
(recommended for safer SSH access) If your IP changes, update this rule.
Avoid 0.0.0.0/0 for SSH unless temporarily needed.

Rule B: - Type: HTTP - Port: 80 - Source: 0.0.0.0/0 - Needed only if the
application will be served on HTTP port 80.

Rule C: - Type: HTTPS - Port: 443 - Source: 0.0.0.0/0 - Needed only if
HTTPS is configured.

Rule D: - Type: Custom TCP - Port: 8080 - Source: 0.0.0.0/0 - Allows
browser access to the Tomcat application on port 8080. For production,
restrict exposure or place it behind a reverse proxy.

Rule E (optional; not required for the SSH-tunnel method): - Type:
Custom TCP - Port: 3308 - Source: My IP - Only needed if connecting
directly to the published MySQL port from a trusted IP. Prefer an SSH
tunnel and do not expose MySQL publicly.

Do not add a MySQL inbound rule unless direct access is specifically
required. The application talks to MySQL over the Docker network, so it
does not need public port 3308.

============================================================ 6. CREATE
THE DOCKER NETWORK
============================================================

The application configuration uses this JDBC URL:
jdbc:mysql://mysql:3306/p04

Therefore, the application container must be able to resolve the
hostname “mysql” on the Docker network.

Create the network if it does not already exist:

sudo docker network create ors-network

If the network already exists, keep using it; do not delete it.

Check networks: sudo docker network ls

============================================================ 7. RUN
MYSQL ON EC2 AND KEEP DATABASE DATA
============================================================

The existing database name is p04. The MySQL container name is
mysql-container and the Docker Hub image used was
lakhanporwal/mysql:8.0.

First inspect what already exists: sudo docker ps -a sudo docker volume
ls sudo docker network inspect ors-network

If the existing mysql-container and its data are already present, do not
remove or recreate it just to deploy a new application image.

If setting up MySQL for the first time, create a persistent Docker
volume: sudo docker volume create mysql-data

Then run MySQL with the volume, network alias “mysql”, and the
environment values that match the application configuration:

sudo docker run -d –restart unless-stopped –name mysql-container
–network ors-network –network-alias mysql -p 3308:3306 -e
MYSQL_ROOT_PASSWORD=root -e MYSQL_DATABASE=p04 -v
mysql-data:/var/lib/mysql lakhanporwal/mysql:8.0

Important: - This first-time command is only for a fresh database
setup. - Do not run it over an existing mysql-container. - Do not remove
mysql-container or mysql-data if you need to preserve existing database
records. - Keep credentials consistent with the deployed
system.properties file. - For a real production system, use stronger
secrets and do not store passwords directly in source code.

If an existing MySQL container is running but is not connected to
ors-network, connect it: sudo docker network connect –alias mysql
ors-network mysql-container

If it is stopped, start it: sudo docker start mysql-container

Check that MySQL responds: sudo docker exec mysql-container mysql -uroot
-proot -e “SHOW DATABASES;”

Expected databases include: p04

Check a simple query: sudo docker exec mysql-container mysql -uroot
-proot -D p04 -e “SELECT 1 AS connection_test;”

Check network alias from the app container after it exists: sudo docker
exec ors-container getent hosts mysql

============================================================ 8. VERIFY
APPLICATION DATABASE CONFIGURATION
============================================================

The deployed application system.properties file should contain the
database values below:

url=jdbc:mysql://mysql:3306/p04 driver=com.mysql.cj.jdbc.Driver
username=root password=root

The remaining pool settings used in the project were: DATABASE=JDBC
service=javaBean acquireIncrement=1 initialPoolSize=1 maxPoolSize=5
minPoolSize=1 timeout=10

The file is inside the deployed WAR at:
WEB-INF/classes/com/sunilos/p4/bundle/system.properties

The hostname must be mysql (not localhost) because the application runs
in a different container from MySQL.

============================================================ 12.
COMPLETE JENKINSFILE
============================================================

Save this file as Jenkinsfile in the Pipeline folder of the DevOps
repository, or use the path configured as Script Path in the Jenkins
Pipeline job.

Important: - This pipeline expects the source repository’s top-level
folder to contain ORSProject04/pom.xml and ORSProject04/Dockerfile. - It
builds the image on the Windows Jenkins machine and pushes it to Docker
Hub. - It deploys only the ORS application container on EC2. It does not
delete the MySQL container or database volume. - The MySQL container
must already exist and be connected to ors-network with alias mysql. -
Update AWS_HOST whenever the EC2 public IP changes.

pipeline { agent any

    environment {
        DOCKER_IMAGE = 'orsproject04'
        DOCKERHUB_IMAGE = 'lakhanporwal/orsproject04:latest'
        AWS_HOST = '54.87.174.177'
    }

    stages {
        stage('Git Checkout') {
            steps {
                git branch: 'main',
                    url: 'https://github.com/lakhan-porwal/ORSProject04-Complete.git'
            }
        }

        stage('Build WAR') {
            steps {
                dir('ORSProject04') {
                    bat 'mvn clean package'
                }
            }
        }

        stage('Build Docker Image') {
            steps {
                dir('ORSProject04') {
                    bat 'docker build -t %DOCKER_IMAGE%:latest .'
                }
            }
        }

        stage('Tag Docker Image') {
            steps {
                bat 'docker tag %DOCKER_IMAGE%:latest %DOCKERHUB_IMAGE%'
            }
        }

        stage('Push to Docker Hub') {
            steps {
                withCredentials([
                    usernamePassword(
                        credentialsId: 'docker-creds-new',
                        usernameVariable: 'DOCKER_USER',
                        passwordVariable: 'DOCKER_PASS'
                    )
                ]) {
                    bat '''
                        @echo off
                        echo %DOCKER_PASS% | docker login -u %DOCKER_USER% --password-stdin
                        if errorlevel 1 exit /b 1
                        docker push %DOCKERHUB_IMAGE%
                        if errorlevel 1 exit /b 1
                        docker logout
                    '''
                }
            }
        }

        stage('Deploy to AWS') {
            steps {
                withCredentials([
                    sshUserPrivateKey(
                        credentialsId: 'aws-ec2-ssh',
                        keyFileVariable: 'SSH_KEY',
                        usernameVariable: 'SSH_USER'
                    )
                ]) {
                    bat '''
                        @echo off
                        ssh -i "%SSH_KEY%" -o StrictHostKeyChecking=no %SSH_USER%@%AWS_HOST% "sudo docker pull %DOCKERHUB_IMAGE% && sudo docker start mysql-container && sudo docker network connect --alias mysql ors-network mysql-container 2>/dev/null || true && sudo docker rm -f ors-container 2>/dev/null || true && sudo docker run -d --restart unless-stopped --name ors-container --network ors-network -p 8080:8080 %DOCKERHUB_IMAGE%"
                        if errorlevel 1 exit /b 1
                    '''
                }
            }
        }

        stage('Verify Containers') {
            steps {
                withCredentials([
                    sshUserPrivateKey(
                        credentialsId: 'aws-ec2-ssh',
                        keyFileVariable: 'SSH_KEY',
                        usernameVariable: 'SSH_USER'
                    )
                ]) {
                    bat '''
                        @echo off
                        ssh -i "%SSH_KEY%" -o StrictHostKeyChecking=no %SSH_USER%@%AWS_HOST% "sudo docker ps"
                    '''
                }
            }
        }
    }

    post {
        success {
            echo 'ORSProject04 CI/CD pipeline completed successfully.'
        }
        failure {
            echo 'Pipeline failed. Review the failing stage in Console Output.'
        }
    }

}

Note: For maximum reliability, if the network alias is already attached,
Docker may report that the alias/network connection already exists.
Verify the current network configuration before using this stage on a
production system. The initial database and network setup should be
completed before the deployment pipeline is run.

============================================================ 13. CREATE
THE JENKINS PIPELINE JOB
============================================================

1.  Open http://localhost:8085.
2.  Select New Item.
3.  Enter a job name, for example: ORSProject04-CI-CD.
4.  Select Pipeline and click OK.
5.  Under Pipeline, choose the method that matches the location of the
    Jenkinsfile.

If the Jenkinsfile is in the ORSProject04 source repository: -
Definition: Pipeline script from SCM - SCM: Git - Repository URL:
https://github.com/lakhan-porwal/ORSProject04-Complete.git - Branch:
*/main - Script Path: ORSProject04/Jenkinsfile, if that is the exact
path in that repository.

If the Jenkinsfile is in the separate DevOps repository: - Set SCM to
the DevOps repository URL. - Script Path: Pipeline/Jenkinsfile, if that
is the exact path in DevOps. - The pipeline itself checks out the
ORSProject04 repository during its Git Checkout stage.

6.  Save the job.
7.  Click Build Now.
8.  Open Console Output and follow each stage.
9.  Confirm the build finishes with SUCCESS.
10. Open the application at:
    http://CURRENT_EC2_PUBLIC_IP:8080/ORSProject04
